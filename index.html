Bab 01 • Dasar Konseptual

Pengantar GUI & Pemrograman Berbasis Event

Mengenal perbedaan mendasar antara CLI dan GUI, sejarah AWT vs Swing, konsep Komponen vs Container, serta bagaimana Event-Driven Programming mengubah alur eksekusi kode Java.

🎯 Tujuan Pembelajaran
  • Menjelaskan perbedaan alur eksekusi procedural CLI vs event-driven GUI.
  • Membedakan karakteristik pustaka AWT (heavyweight) dengan Java Swing (lightweight).
  • Memahami relasi hierarkis antara Komponen visual dan Wadah Container.
  • Menjalankan program GUI pertama menggunakan Event Dispatch Thread (EDT).

1. CLI vs GUI: Perubahan Paradigma Interaksi

Pada aplikasi konsol (CLI), alur eksekusi bersifat sekuensial dan prosedural. Program menentukan kapan pengguna harus menginput data:

Prompt Nama → Scanner membaca nama → Prompt Umur → Scanner membaca umur → Cetak hasil → Program Selesai.

Sebaliknya, pada GUI (Graphical User Interface), kendali berada di tangan pengguna! Pengguna bebas memilih: apakah ingin langsung menekan tombol, mencentang kotak, memilih gambar, atau menutup jendela. Program tidak lagi berjalan linier, melainkan berada dalam status mendengarkan (listening) dan baru bereaksi ketika terjadi suatu Event (kejadian). Paradigma ini disebut Event-Driven Programming.

2. AWT vs Java Swing: Mengapa Kita Menggunakan Swing?

Java memiliki dua pustaka GUI bawaan standar di dalam paket JDK:

  • AWT (Abstract Window Toolkit): Pustaka generasi pertama (paket java.awt). Bersifat Heavyweight karena setiap tombol atau jendela meminjam komponen native milik sistem operasi (Windows, Linux, macOS). Akibatnya, tampilan aplikasi terlihat berbeda-beda di tiap OS dan kustomisasinya sangat terbatas.
  • Java Swing: Pustaka generasi modern (paket javax.swing). Bersifat Lightweight karena ditulis murni 100% dalam Java dan digambar langsung di layar menggunakan Java 2D. Hasilnya: tampilan seragam, konsisten, mendukung sistem tema fleksibel, dan memiliki komponen yang jauh lebih kaya.
💡 Ciri Khas Penamaan Komponen Swing

Seluruh komponen Swing diawali dengan huruf kapital 'J' untuk membedakannya dari komponen AWT lama: JFrame (bukan Frame), JButton (bukan Button), JLabel (bukan Label), dan JPanel (bukan Panel).

3. Konsep Komponen dan Container

Dalam merancang GUI, bayangkan sebuah meja kafe:

  • Container (Wadah): Adalah meja atau nampannya. Container bertugas menampung benda-benda lain. Contoh container: JFrame (jendela utama), JPanel (nampan penyekat).
  • Component (Komponen): Adalah cangkir kopi, piring kue, dan sendoknya. Komponen adalah elemen individual yang memiliki fungsi spesifik. Contoh: JLabel (label teks/gambar), JButton (tombol aksi), JCheckBox (pilihan centang).

4. Contoh Program Pertama: HaloSwing

Mari kita bedah kode program GUI paling sederhana yang menampilkan salam di layar desktop:

📄 HaloSwing.java 
package examples.pengantar;

import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.SwingConstants;
import javax.swing.SwingUtilities;
import java.awt.Font;

/**
 * Contoh 01: HaloSwing
 * Program GUI paling sederhana menggunakan Java Swing.
 */
public class HaloSwing {
    public static void main(String[] args) {
        // Menjalankan GUI di Event Dispatch Thread (EDT) untuk keamanan thread
        SwingUtilities.invokeLater(() -> {
            // 1. Membuat objek JFrame sebagai jendela utama
            JFrame frame = new JFrame("Aplikasi Pertama Saya - Java Swing");

            // 2. Menentukan aksi saat tombol close (X) ditekan
            frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

            // 3. Menentukan ukuran jendela (lebar x tinggi dalam pixel)
            frame.setSize(400, 250);

            // 4. Meletakkan jendela tepat di tengah layar monitor
            frame.setLocationRelativeTo(null);

            // 5. Membuat komponen teks (JLabel) dengan alignment di tengah
            JLabel labelSalam = new JLabel("Halo Mahasiswa PBO! Selamat Datang di Swing.", SwingConstants.CENTER);
            labelSalam.setFont(new Font("Segoe UI", Font.BOLD, 14));

            // 6. Menambahkan label ke dalam frame
            frame.add(labelSalam);

            // 7. Menampilkan jendela ke layar pengguna
            frame.setVisible(true);
        });
    }
}

5. Bedah Baris Kode Kunci

  • SwingUtilities.invokeLater(() -> { ... });
    Instruksi ini memastikan pembuatan jendela dijalankan di dalam Event Dispatch Thread (EDT). Swing tidak bersifat thread-safe, sehingga seluruh operasi GUI wajib diserahkan ke EDT agar terhindar dari konflik proses.
  • JFrame frame = new JFrame("...");
    Membuat objek jendela utama desktop lengkap dengan baris judul di bagian atas.
  • frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
    Menginstruksikan Java agar menghentikan total proses program (JVM) saat pengguna menekan tombol silang merah (X) di pojok jendela.
  • frame.setLocationRelativeTo(null);
    Perintah sakti untuk memposisikan jendela tepat di titik koordinat tengah monitor pengguna secara otomatis.
  • frame.setVisible(true);
    Secara default, objek frame diciptakan dalam keadaan tersembunyi (invisible) di memori. Method ini memunculkannya ke pandangan pengguna.

Bab 02 • Jendela Utama

Membuat Jendela dengan JFrame

Menguasai konfigurasi properti dasar jendela aplikasi, menerapkan prinsip pewarisan OOP (Inheritance) dengan membuat kelas turunan JFrame, serta mengunci ukuran dan memposisikan window di tengah layar.

🎯 Tujuan Pembelajaran
  • Memahami fungsi dan siklus hidup jendela JFrame.
  • Menerapkan prinsip OOP dengan mendefinisikan kelas yang extends JFrame.
  • Mengkonfigurasi 6 method esensial: setTitle, setSize, setDefaultCloseOperation, setLocationRelativeTo, setResizable, dan setVisible.
  • Menjelaskan alasan teknis di balik penguncian dimensi jendela (fixed-size window).

1. Mengapa Menggunakan 'extends JFrame'?

Pada Bab 1, kita membuat objek frame secara prosedural di method main: JFrame frame = new JFrame();. Cara tersebut cukup untuk demo mini, tetapi melanggar prinsip desain OOP saat aplikasi bertumbuh besar.

Praktik terbaik di dunia industri adalah menerapkan Inheritance: kita mendefinisikan kelas aplikasi kita sendiri (misalnya JendelaUtama atau MainApp) sebagai turunan dari JFrame:

public class JendelaUtama extends JFrame { ... }

Dengan cara ini, kelas JendelaUtama mewarisi seluruh kemampuan sebuah jendela, memiliki hak untuk mengonfigurasi dirinya sendiri di dalam constructor (Encapsulation), dan method main menjadi sangat bersih: hanya bertugas membuat satu objek dan memanggil setVisible(true)!

2. Enam Method Konfigurasi Wajib pada JFrame

Berikut adalah 6 konfigurasi fundamental yang harus selalu Anda ingat:

Method Parameter Contoh Fungsi & Perilaku
setTitle(String) "JavaCafe POS" Mengatur teks judul pada title bar atas jendela.
setSize(int, int) 520, 350 Menentukan lebar dan tinggi jendela dalam satuan pixel.
setDefaultCloseOperation JFrame.EXIT_ON_CLOSE Menghentikan JVM saat jendela ditutup oleh pengguna.
setLocationRelativeTo null Menempatkan jendela tepat di tengah monitor (wajib dipanggil setelah setSize).
setResizable(boolean) false Mengunci ukuran agar pengguna tidak dapat memperbesar/mengecilkan window.
setVisible(boolean) true Menampilkan frame ke layar (selalu panggil paling akhir).

3. Contoh Kode: JendelaUtama.java

Perhatikan bagaimana seluruh pengaturan jendela dibungkus rapi di dalam constructor kelas:

📄 JendelaUtama.java 
package examples.jframedesar;

import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.SwingConstants;
import javax.swing.SwingUtilities;
import java.awt.Color;
import java.awt.Font;

/**
 * Contoh 02: JendelaUtama
 * Menunjukkan praktik terbaik OOP dengan membuat kelas turunan dari JFrame.
 */
public class JendelaUtama extends JFrame {

    public JendelaUtama() {
        // Mengatur judul jendela melalui super constructor atau setTitle()
        super("JavaCafe POS - Sistem Kasir V1.0");

        // 1. Ukuran jendela: 520 x 350 pixel
        setSize(520, 350);

        // 2. Program berhenti total saat jendela ditutup
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

        // 3. Jendela otomatis muncul di tengah layar monitor
        setLocationRelativeTo(null);

        // 4. Kunci ukuran agar pengguna tidak bisa mengubah dimensi jendela
        setResizable(false);

        // 5. Inisialisasi komponen tampilan
        initComponent();
    }

    private void initComponent() {
        JLabel labelSelamat = new JLabel("Selamat Datang di JavaCafe POS", SwingConstants.CENTER);
        labelSelamat.setFont(new Font("Segoe UI", Font.BOLD, 18));
        labelSelamat.setForeground(new Color(30, 41, 59));

        // Menambahkan label ke content pane JFrame
        add(labelSelamat);
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            JendelaUtama app = new JendelaUtama();
            // Menampilkan jendela
            app.setVisible(true);
        });
    }
}

Banyak mahasiswa terbiasa menulis setVisible(true); di baris terakhir constructor frame. Kebiasaan ini rawan memicu bug thread race condition pada subclass yang kompleks. Praktik terbaik: panggil app.setVisible(true); dari method main setelah objek frame selesai diinstansiasi secara utuh.

📝 Ringkasan Bab 2
  • Pola public class KelasKu extends JFrame adalah standar OOP untuk membangun jendela desktop di Java.
  • setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE) wajib dipasang agar proses JVM benar-benar berhenti saat window ditutup.
  • setLocationRelativeTo(null) menempatkan jendela di pusat layar secara otomatis.
  • setResizable(false) menjaga stabilitas tata letak komponen agar tidak berantakan ditarik oleh pengguna.

Bab 03 • Arsitektur Modular

Container Fleksibel dengan JPanel

Mencegah penumpukan kode pada satu file dengan membuat kelas panel khusus (extends JPanel), memahami peran container perantara, serta menghubungkan panel anak dengan frame induk melalui passing referensi constructor (Dependency Injection).

🎯 Tujuan Pembelajaran
  • Memahami perbedaan peran antara top-level container (JFrame) dan intermediate container (JPanel).
  • Mendefinisikan kelas komponen modular dengan mewarisi JPanel (extends JPanel).
  • Menerapkan teknik passing referensi objek frame induk ke dalam constructor kelas panel anak.
  • Menghubungkan interaksi antara panel anak dan frame utama secara bersih tanpa membuat objek duplikat.

1. Masalah "God Class" pada Pemula GUI

Kesalahan paling umum yang dilakukan mahasiswa saat pertama kali membuat GUI adalah menaruh semua hal di dalam satu file JFrame: deklarasi 50 tombol, 20 label, layouting 3 halaman berbeda, dan semua event listener ditulis berjejal dalam satu file hingga mencapai ribuan baris!

Hal ini menciptakan apa yang disebut dalam software engineering sebagai God Class (kelas monster yang serba tahu dan serba mengatur), yang sangat rapuh, sulit dibaca, dan hampir mustahil diperbaiki jika ada bug.

2. Solusi: Arsitektur Modular Berbasis JPanel

Solusi elegannya adalah membagi tampilan menjadi modul-modul terpisah:

  • AppFrame.java: Khusus bertindak sebagai bingkai jendela utama dan pengatur alur halaman.
  • MenuPanel.java: Khusus menangani tampilan katalog menu (turunan dari JPanel).
  • PesananPanel.java: Khusus menangani formulir detail pesanan dan kustomisasi (turunan dari JPanel).

3. Pola Passing Referensi Frame Induk (Dependency Injection)

Pertanyaan krusial: "Jika panel berada di kelas terpisah, bagaimana tombol di dalam MenuPanel bisa memberitahu AppFrame untuk berpindah halaman atau menampilkan dialog?"

Jawabannya: Kirimkan referensi frame utama lewat parameter constructor panel!

// Di dalam MenuPanel.java
private final AppFrame parentFrame;

public MenuPanel(AppFrame parentFrame) {
    this.parentFrame = parentFrame;
}

Dengan menyimpan referensi parentFrame, objek panel anak dapat memanggil method publik milik frame kapan saja saat tombol di panel ditekan!

4. Contoh Kode Implementasi

Perhatikan keterhubungan antara kedua kelas di bawah ini:

📄 MenuPanel.java (Panel Anak) 
package examples.jpanelmodular;

import javax.swing.JButton;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.SwingConstants;
import java.awt.BorderLayout;
import java.awt.Color;
import java.awt.Font;

/**
 * Contoh 03a: MenuPanel
 * Sebuah panel kustom yang menerima referensi frame induknya.
 */
public class MenuPanel extends JPanel {

    // Menyimpan referensi ke frame induk agar dapat memicu method pada frame
    private final AppFrame parentFrame;

    public MenuPanel(AppFrame parentFrame) {
        this.parentFrame = parentFrame;

        // Mengatur layout panel
        setLayout(new BorderLayout(10, 10));
        setBackground(new Color(241, 245, 249));

        initUI();
    }

    private void initUI() {
        JLabel titleLabel = new JLabel("Menu Pilihan JavaCafe", SwingConstants.CENTER);
        titleLabel.setFont(new Font("Segoe UI", Font.BOLD, 16));
        add(titleLabel, BorderLayout.NORTH);

        JLabel descLabel = new JLabel("Silakan klik tombol di bawah untuk pesan:", SwingConstants.CENTER);
        add(descLabel, BorderLayout.CENTER);

        JButton orderButton = new JButton("Buka Form Pesanan");
        // Menggunakan referensi parentFrame untuk memanggil method di frame utama
        orderButton.addActionListener(e -> {
            parentFrame.tampilkanPesan("Tombol ditekan dari dalam MenuPanel!");
        });

        add(orderButton, BorderLayout.SOUTH);
    }
}
📄 AppFrame.java (Frame Induk) 
package examples.jpanelmodular;

import javax.swing.JFrame;
import javax.swing.JOptionPane;
import javax.swing.SwingUtilities;

/**
 * Contoh 03b: AppFrame
 * Frame utama yang menampung MenuPanel dan menyediakan method publik untuk dipanggil panel.
 */
public class AppFrame extends JFrame {

    private final MenuPanel menuPanel;

    public AppFrame() {
        super("Aplikasi Modular Swing - JavaCafe");
        setSize(520, 350);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setResizable(false);

        // Mengirim 'this' (objek frame ini) ke constructor MenuPanel
        this.menuPanel = new MenuPanel(this);

        // Menambahkan panel ke frame
        add(menuPanel);
    }

    // Method publik yang bisa diakses oleh kelas panel anak
    public void tampilkanPesan(String pesan) {
        JOptionPane.showMessageDialog(this, pesan, "Informasi Frame", JOptionPane.INFORMATION_MESSAGE);
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            new AppFrame().setVisible(true);
        });
    }
}

Bab 04 • Elemen Interaktif

Komponen Dasar: JLabel, JButton, dan JCheckBox

Menguasai anatomi tiga komponen visual paling esensial dalam aplikasi kasir dan formulir: JLabel (teks dan gambar), JButton (tombol aksi), serta JCheckBox (pilihan add-on independen) lengkap dengan kustomisasi font, warna, dan perataan.

🎯 Tujuan Pembelajaran
  • Mengkonfigurasi JLabel: manipulasi teks, font, warna, dan perataan horizontal (SwingConstants).
  • Mengkonfigurasi JButton: styling warna latar belakang, warna teks, dan menghilangkan outline focus.
  • Menggunakan JCheckBox untuk opsi checklist/add-on yang dapat dipilih secara bebas.
  • Membaca status pilihan pengguna dengan method isSelected().

1. JLabel: Menampilkan Teks & Keterangan

JLabel adalah komponen pasif (read-only) yang digunakan untuk menyajikan judul, teks petunjuk, rincian harga, atau gambar status:

  • setText(String text): Mengubah teks label secara dinamis saat runtime.
  • setFont(Font font): Mengatur jenis huruf (font family, style, size), contoh: new Font("Segoe UI", Font.BOLD, 16).
  • setForeground(Color color): Mengubah warna huruf teks.
  • setHorizontalAlignment(SwingConstants.CENTER): Mengatur posisi teks (LEFT, CENTER, RIGHT).

2. JButton: Tombol Aksi Pengguna

JButton adalah komponen aktif yang memicu proses komputasi saat diklik oleh pengguna:

  • setBackground(Color color): Mengatur warna latar belakang tombol.
  • setForeground(Color color): Mengatur warna teks di dalam tombol.
  • setFocusPainted(false): Menghilangkan garis putus-putus fokus saat tombol diklik (membuat tombol terlihat lebih rapi dan modern).

3. JCheckBox: Kotak Centang Opsi Add-on

JCheckBox adalah kotak pilihan dengan status biner (tercentang / tidak tercentang). Berbeda dengan RadioButton yang hanya mengizinkan memilih 1 opsi dalam grup, JCheckBox bersifat independen: pengguna bisa mencentang nol opsi, satu opsi, atau semua opsi sekaligus.

Karakteristik inilah yang menjadikannya pilihan sempurna untuk opsi Add-on / Topping pada aplikasi pemesanan makanan/minuman kafe!

  • isSelected(): Mengembalikan nilai true jika kotak sedang dicentang, atau false jika kosong.
  • setSelected(boolean b): Mengubah status centang secara programatik (sangat berguna untuk fitur Reset Form).

Bab 05 • Aset Multimedia

Menangani Gambar dengan ImageIcon

Menampilkan logo dan foto produk ke dalam antarmuka GUI, mengatur struktur folder aset dengan path relatif yang aman, melakukan penskalaan (resize) gambar secara proporsional, serta menghindari jebakan umum gambar hilang.

🎯 Tujuan Pembelajaran
  • Memahami cara kerja kelas ImageIcon dan integrasinya dengan JLabel.
  • Mengelola path relatif file gambar pada struktur proyek Java desktop.
  • Menggunakan method Image.getScaledInstance() dengan algoritma SCALE_SMOOTH.
  • Mengidentifikasi dan mengatasi penyebab gambar tidak tampil di layar.

1. Anatomi Menampilkan Gambar di Java Swing

Di Swing, tidak ada komponen khusus bernama JImage. Gambar ditampilkan dengan cara memasukkan objek ImageIcon ke dalam sebuah JLabel menggunakan method label.setIcon(icon) atau melalui constructor label: new JLabel(icon).

2. Jebakan Path Relatif vs Path Absolut

Salah satu kesalahan paling sering yang membuat program gagal saat diuji oleh asisten adalah penggunaan Path Absolut:

// ❌ SALAH BESAR (Hanya jalan di laptop Anda sendiri!):
ImageIcon icon = new ImageIcon("C:\\Users\\NamaAnda\\Documents\\proyek\\kopi.png");

Saat kode tersebut dijalankan di laptop asisten atau komputer laboratorium, program langsung gagal memuat gambar karena path tersebut tidak ada!

Gunakan selalu Path Relatif terhadap direktori kerja (working directory) proyek:

// ✅ BENAR (Berjalan di komputer manapun):
ImageIcon icon = new ImageIcon("assets/img/coffee.png");

3. Melakukan Penskalaan (Resize) Gambar

File gambar mentah dari kamera atau desainer sering kali memiliki resolusi besar (misal 1024x1024 pixel). Jika langsung dimasukkan ke JLabel di jendela berukuran 520x350, gambar akan memakan seluruh layar jendela!

Kita perlu mengecilkannya secara proporsional melalui 3 langkah berurutan:

  1. Ambil objek Image dari ImageIcon mentah: Image rawImage = iconAsli.getImage();.
  2. Skala ukurannya: Image scaledImage = rawImage.getScaledInstance(100, 100, Image.SCALE_SMOOTH);.
  3. Bungkus kembali ke ImageIcon baru: ImageIcon finalIcon = new ImageIcon(scaledImage);.

Berikut adalah implementasi lengkap yang dilengkapi penanganan graceful jika file tidak ditemukan:

package examples.imageicondemo;

import javax.swing.ImageIcon;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.SwingConstants;
import javax.swing.SwingUtilities;
import java.awt.BorderLayout;
import java.awt.Color;
import java.awt.Font;
import java.awt.Image;
import java.io.File;

/**
 * Contoh 05: GambarDemo
 * Memuat, memeriksa, melakukan resize, dan menampilkan gambar pada JLabel.
 */
public class GambarDemo extends JFrame {

    private JLabel labelGambar;
    private JLabel labelKeterangan;

    public GambarDemo() {
        super("Demo Menampilkan Gambar dengan ImageIcon");
        setSize(520, 350);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setResizable(false);

        initComponents();
    }

    private void initComponents() {
        JPanel panel = new JPanel(new BorderLayout(10, 10));
        panel.setBackground(Color.WHITE);

        // Path relatif ke file gambar
        String pathGambar = "assets/img/coffee.png";
        File fileGambar = new File(pathGambar);

        labelGambar = new JLabel("", SwingConstants.CENTER);

        // JEBAKAN UMUM: Memastikan file benar-benar ada sebelum dimuat
        if (fileGambar.exists()) {
            ImageIcon iconAsli = new ImageIcon(pathGambar);

            // Opsional: Melakukan scaling gambar agar pas dengan tampilan
            Image gambarTerskala = iconAsli.getImage().getScaledInstance(100, 100, Image.SCALE_SMOOTH);
            labelGambar.setIcon(new ImageIcon(gambarTerskala));
            labelGambar.setText("Ikon Kopi Berhasil Dimuat");
            labelGambar.setHorizontalTextPosition(SwingConstants.CENTER);
            labelGambar.setVerticalTextPosition(SwingConstants.BOTTOM);
        } else {
            // Penanganan graceful jika file tidak ditemukan
            labelGambar.setText("⚠️ Gambar tidak ditemukan di: " + pathGambar);
            labelGambar.setForeground(Color.RED);
        }

        labelKeterangan = new JLabel("Contoh gambar produk JavaCafe POS", SwingConstants.CENTER);
        labelKeterangan.setFont(new Font("Segoe UI", Font.ITALIC, 13));

        panel.add(labelGambar, BorderLayout.CENTER);
        panel.add(labelKeterangan, BorderLayout.SOUTH);

        add(panel);
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> new GambarDemo().setVisible(true));
    }
}

Bab 06 • Tata Letak Responsif

Menguasai Layout Manager & Nested Panels

Memahami filosofi Layout Manager dalam mengontrol posisi dan ukuran komponen secara otomatis, menguasai tiga layout utama (BorderLayout, GridLayout, FlowLayout), dan menerapkan teknik Nested Layout (panel di dalam panel).

🎯 Tujuan Pembelajaran
  • Memahami kelemahan fatal Absolute Layout (setLayout(null)).
  • Menguasai karakteristik BorderLayout, GridLayout, dan FlowLayout.
  • Menerapkan arsitektur Nested Layout untuk merancang antarmuka profesional.
  • Menentukan pilihan layout yang tepat sesuai kebutuhan struktur layar.

1. Mengapa Kita Tidak Boleh Menggunakan 'null layout'?

Banyak tutorial jadul mengajarkan mahasiswa menggunakan setLayout(null); lalu menaruh komponen dengan koordinat manual: komponen.setBounds(x, y, width, height);.

Mengapa Absolute Layout dilarang di dunia nyata?

  • Setiap sistem operasi (Windows vs macOS vs Linux) memiliki ketebalan font dan rendering tombol yang berbeda beberapa pixel. Koordinat kaku yang terlihat rapi di laptop Anda bisa menjadi terpotong atau teks terpotong di laptop asisten!
  • Sulit dirawat: jika Anda ingin menyisipkan satu baris baru di tengah form, Anda terpaksa menghitung ulang koordinat Y untuk seluruh komponen di bawahnya!

Sebagai gantinya, Java menyediakan Layout Manager: objek manajer yang secara cerdas dan otomatis mengatur ukuran dan penataan komponen.

2. Tiga Layout Manager Fundamental

A. BorderLayout (Default pada JFrame)

Membagi kontainer menjadi 5 zona: NORTH, SOUTH, EAST, WEST, dan CENTER. Karakteristik penting: Area CENTER akan otomatis meregang mengisi seluruh sisa ruang kosong yang tidak ditempati oleh keempat sisi lainnya.

B. GridLayout

Membagi kontainer menjadi matriks baris dan kolom yang berukuran seragam persis sama rata: new GridLayout(rows, cols, hgap, vgap). Sangat cocok untuk formulir bertingkat (misal kolom label di kiri dan input di kanan) atau katalog produk berpetak.

C. FlowLayout (Default pada JPanel)

Menyusun komponen mengalir berurutan dari kiri ke kanan layaknya kata-kata dalam satu baris paragraf: new FlowLayout(alignment, hgap, vgap). Sangat cocok untuk deretan tombol aksi di bagian bawah layar (misal tombol Batal dan Simpan).

3. Rahasia Desain GUI Profesional: Nested Layout

Sebuah layar aplikasi modern jarang sekali hanya menggunakan satu layout manager tunggal. Kunci menciptakan tampilan yang rapi adalah Nested Layout (Panel Bersarang di dalam Panel):

  • Root Container: Menggunakan BorderLayout.
  • Bagian Atas (NORTH): Diberi JLabel header.
  • Bagian Tengah (CENTER): Diberi JPanel dengan GridLayout berisi menu pilihan.
  • Bagian Bawah (SOUTH): Diberi JPanel dengan FlowLayout berisi tombol navigasi/aksi.

package examples.layoutmanager;

import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.SwingConstants;
import javax.swing.SwingUtilities;
import java.awt.BorderLayout;
import java.awt.Color;
import java.awt.FlowLayout;
import java.awt.Font;
import java.awt.GridLayout;

/**
 * Contoh 06: LayoutDemo
 * Menggabungkan BorderLayout, GridLayout, dan FlowLayout (Nested Layout).
 */
public class LayoutDemo extends JFrame {

    public LayoutDemo() {
        super("Eksplorasi Layout Manager & Nested Panels");
        setSize(520, 350);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setResizable(false);

        initLayout();
    }

    private void initLayout() {
        // 1. Container Utama menggunakan BorderLayout
        JPanel mainPanel = new JPanel(new BorderLayout(8, 8));
        mainPanel.setBackground(new Color(241, 245, 249));

        // 2. BAGIAN ATAS (NORTH): Header
        JLabel headerLabel = new JLabel("JavaCafe POS - Nested Layout Demo", SwingConstants.CENTER);
        headerLabel.setFont(new Font("Segoe UI", Font.BOLD, 15));
        headerLabel.setOpaque(true);
        headerLabel.setBackground(new Color(30, 58, 138));
        headerLabel.setForeground(Color.WHITE);
        mainPanel.add(headerLabel, BorderLayout.NORTH);

        // 3. BAGIAN TENGAH (CENTER): Grid 2x2 Menu Minuman
        JPanel gridMenuPanel = new JPanel(new GridLayout(2, 2, 8, 8));
        gridMenuPanel.setBackground(new Color(241, 245, 249));

        JButton btn1 = new JButton("1. Espresso (Rp 18.000)");
        JButton btn2 = new JButton("2. Americano (Rp 20.000)");
        JButton btn3 = new JButton("3. Caffe Latte (Rp 24.000)");
        JButton btn4 = new JButton("4. Caramel Macchiato (Rp 28.000)");

        gridMenuPanel.add(btn1);
        gridMenuPanel.add(btn2);
        gridMenuPanel.add(btn3);
        gridMenuPanel.add(btn4);

        mainPanel.add(gridMenuPanel, BorderLayout.CENTER);

        // 4. BAGIAN BAWAH (SOUTH): FlowLayout untuk Tombol Aksi
        JPanel actionPanel = new JPanel(new FlowLayout(FlowLayout.RIGHT, 10, 5));
        actionPanel.setBackground(new Color(226, 232, 240));

        JButton btnBatal = new JButton("Batal");
        JButton btnLanjut = new JButton("Lanjut ke Pembayaran");
        btnLanjut.setBackground(new Color(245, 158, 11));
        btnLanjut.setForeground(Color.BLACK);

        actionPanel.add(btnBatal);
        actionPanel.add(btnLanjut);

        mainPanel.add(actionPanel, BorderLayout.SOUTH);

        add(mainPanel);
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> new LayoutDemo().setVisible(true));
    }
}

Bab 07 • Navigasi Layar Tunggal

Navigasi Halaman dengan CardLayout

Memahami arsitektur kartu bertumpuk untuk berpindah antar-halaman secara mulus di dalam satu jendela JFrame berukuran tetap, mendaftarkan panel halaman dengan key unik, dan mengontrol navigasi bolak-balik dari berbagai kelas.

🎯 Tujuan Pembelajaran
  • Menjelaskan konsep kerja CardLayout sebagai tumpukan kartu visual.
  • Mendaftarkan panel-panel halaman ke kontainer utama menggunakan kunci String pengenal.
  • Melakukan perpindahan halaman maju dan mundur menggunakan method cardLayout.show().
  • Menyediakan method pengendali publik pada frame agar navigasi dapat dipicu dari tombol di dalam panel anak.

1. Mengapa Multi-Window Pop-up Dihindari?

Saat pemula ingin membuat aplikasi yang memiliki Halaman 1 (Katalog) dan Halaman 2 (Form Pesanan), mereka kerap membuat dua JFrame terpisah: saat tombol diklik, jendela 1 ditutup dan jendela 2 dibuka secara melompat (pop-up baru).

Pendekatan tersebut menghasilkan pengalaman pengguna yang buruk: layar berkedip, posisi jendela melompat-lompat di monitor, dan memakan resource ganda.

Standar aplikasi modern adalah Single Window Application: jendela aplikasi tetap satu (misal berukuran tetap 520x350 pixel), namun isi halamannya berganti secara mulus di tempat. Inilah fungsi utama dari CardLayout!

2. Cara Kerja CardLayout: Analogi Setumpuk Kartu

Bayangkan setumpuk kartu remi atau kartu flashcard:

  • Seluruh kartu bertumpuk di posisi yang sama persis di atas meja.
  • Hanya ada satu kartu teratas yang tampak oleh mata kita pada satu waktu.
  • Setiap kartu diberi nama pengenal (label nama unik).

Bab 08 • Estetika & Spasi

Kerapian Tampilan dengan Swing Border

Menghilangkan tampilan antarmuka yang sempit dan menabrak batas layar menggunakan BorderFactory, menerapkan EmptyBorder untuk menciptakan ruang napas (padding/margin), serta menggabungkan border garis dengan CompoundBorder.

🎯 Tujuan Pembelajaran
  • Memahami peran penting ruang kosong (whitespace/padding) dalam kenyamanan visual UI.
  • Menggunakan BorderFactory.createEmptyBorder() untuk memberikan padding/margin.
  • Menggunakan BorderFactory.createLineBorder() untuk garis pembatas kartu produk.
  • Mengkombinasikan border luar dan bantalan dalam dengan BorderFactory.createCompoundBorder().

1. Masalah "Komponen Menabrak Dinding"

Secara default, komponen yang dimasukkan ke dalam JFrame atau JPanel akan menempel ketat tepat di tepi batas piksel terluar. Teks menabrak pinggir bingkai, tombol bersentuhan dengan dinding kaca jendela, dan layout terlihat sesak serta tidak profesional.

Di dunia desain UI, kita membutuhkan Padding (ruang napas di dalam batas elemen) dan Margin (ruang napas di luar batas elemen). Di Java Swing, kedua hal ini dicapai melalui kelas Border!

2. Ragam Border Populer dari BorderFactory

Java menyediakan kelas utilitas BorderFactory dengan metode statis siap pakai:

  • EmptyBorder (Bantalan Tak Kasat Mata):
    BorderFactory.createEmptyBorder(top, left, bottom, right)
    Border ini tidak menggambar garis apapun, melainkan memberikan ruang kosong transparan (padding) di sekeliling komponen.
  • LineBorder (Garis Tepi):
    BorderFactory.createLineBorder(Color.LIGHT_GRAY, 1)
    Menggambar garis batas tipis yang rapi untuk memisahkan kartu konten.
  • CompoundBorder (Border Majemuk):
    BorderFactory.createCompoundBorder(garisLuar, bantalanDalam)
    Trik sakti profesional: menggabungkan garis tepi di luar dengan ruang padding di dalam sehingga isi teks tidak menempel ke garis!

Bab 09A • Fondasi Event Handling

Fondasi Event Handling & 4 Gaya Penulisan Listener

Memahami Event-Driven Architecture sebagai penerapan nyata konsep Interface dan Polimorfisme OOP, membedah siklus kejadian (Event Model), mengekstrak informasi Event Object, serta membandingkan 4 gaya penulisan listener pada satu kasus yang sama.

🎯 Tujuan Pembelajaran
  • Menjelaskan hubungan arsitektur Event Handling Swing dengan materi Interface & Polimorfisme (Modul 2).
  • Menguraikan siklus Event Model: Event Source, Event Object, dan Event Listener.
  • Mengekstrak informasi penting dari objek event: getSource(), getActionCommand(), koordinat, dan tombol keyboard.
  • Mengimplementasikan 4 gaya penulisan listener pada satu kasus penghitung porsi kopi kafe.
  • Mengelola banyak tombol dengan satu listener terpusat secara aman.

1. Model Event: Analogi Bel Pintu Kafe

Pada aplikasi konsol prosedural (CLI), program berjalan secara diktator: program menentukan kapan giliran membaca input dan kapan mencetak output. Pada GUI, pengguna memegang kendali penuh. Program berada dalam kondisi pasif "mendengarkan" hingga terjadi suatu interaksi.

Mekanisme ini bekerja melalui Tripartit Event Model:

  • 1. Event Source (Sumber Kejadian): Komponen visual yang disentuh pengguna, misalnya saklar bel pintu di depan kafe (objek JButton).
  • 2. Event Object (Informasi Kejadian): Saat saklar ditekan, sistem secara otomatis membungkus semua fakta kejadian ke dalam sebuah objek (misalnya ActionEvent). Objek ini memuat: siapa yang menekan, jam berapa, tombol apa yang ditekan, dsb.
  • 3. Event Listener (Pendengar Kejadian): Barista di dalam kafe yang telinganya siap mendengar bel pintu. Begitu sinyal tiba, barista segera bergerak membuatkan pesanan (method actionPerformed() dieksekusi).

2. Hubungan dengan OOP: Listener Adalah Interface!

Banyak pemula mengira addActionListener adalah "mantra ajaib". Padahal, ini adalah penerapan murni dari materi Interface & Polimorfisme yang telah Anda pelajari pada Modul 2!

💡 Mengapa Java Swing Menggunakan Interface untuk Event?

Bayangkan jika Java menggunakan pewarisan kelas (Inheritance) untuk listener: karena Java hanya mendukung *Single Inheritance*, kelas MainFrame Anda tidak akan bisa mewarisi JFrame sekaligus mewarisi ButtonListener!

Dengan menggunakan Interface (Observer Pattern):

  • Loose Coupling (Keterikatan Longgar): Tombol JButton tidak perlu tahu siapa yang mendengarkannya. Ia hanya tahu: "Siapapun objek yang mendaftar ke saya asalkan mengimplementasikan kontrak interface ActionListener, saya jamin akan memanggil method actionPerformed()-nya saat saya diklik!"
  • Multiple Implementations: Satu kelas window di Java bebas mengimplementasikan 3, 5, atau 10 interface listener sekaligus (misal: implements ActionListener, ItemListener, WindowListener).

3. Anatomi Objek Event: Menggali Informasi Aksi

Method pada interface listener selalu menerima parameter berupa objek event (misal ActionEvent e, MouseEvent e, KeyEvent e). Objek ini membawa method-method sakti:

  • e.getSource(): Mengembalikan referensi objek komponen pemancar aksi (bertipe Object). Dapat dibandingkan dengan operator == untuk mendeteksi komponen mana yang diklik: if (e.getSource() == btnPesan).
  • e.getActionCommand(): Mengembalikan teks perintah (String). Secara default bernilai sama dengan teks pada tombol, kecuali diubah via btn.setActionCommand("KODE_AKSI").
  • e.getX() dan e.getY(): (Pada MouseEvent) Mengembalikan titik koordinat piksel kursor mouse saat aksi berlangsung.
  • e.getKeyChar() dan e.getKeyCode(): (Pada KeyEvent) Mengetahui karakter huruf atau kode tombol hardware keyboard yang ditekan.

import javax.swing.JFrame;

import javax.swing.SwingUtilities;

/**
 * Contoh 09A: EmpatGayaListenerDemo
 * Menunjukkan 4 cara berbeda dalam menulis ActionListener untuk kasus yang sama:
 * Counter Tambah Porsi Kopi JavaCafe.
 *
 * Gaya 1: Named Class terpisah (Outer / Inner Class biasa)
 * Gaya 2: Frame/Panel itu sendiri (implements ActionListener)
 * Gaya 3: Anonymous Inner Class
 * Gaya 4: Lambda Expression & Method Reference
 */
public class EmpatGayaListenerDemo extends JFrame implements ActionListener {

    private int jumlahPorsi = 0;
    private JLabel lblCounter;
    private JLabel lblStatusGaya;

    // Tombol untuk masing-masing gaya
    private JButton btnGaya1; // Named Class
    private JButton btnGaya2; // Implements di Frame
    private JButton btnGaya3; // Anonymous Inner Class
    private JButton btnGaya4; // Lambda Expression
    private JButton btnReset; // Method Reference

    public EmpatGayaListenerDemo() {
        super("Perbandingan 4 Gaya Penulisan Listener - JavaCafe");
        setSize(540, 380);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setResizable(false);

        initComponents();
        setupListeners();
    }

    private void initComponents() {
        JPanel root = new JPanel(new BorderLayout(10, 10));
        root.setBackground(new Color(248, 250, 252));

        // Header Counter
        JPanel pnlHeader = new JPanel(new GridLayout(2, 1, 4, 4));
        pnlHeader.setBackground(new Color(30, 58, 138));

        JLabel lblJudul = new JLabel("Pemesanan Espresso Shot", SwingConstants.CENTER);
        lblJudul.setFont(new Font("Segoe UI", Font.BOLD, 15));
        lblJudul.setForeground(Color.WHITE);

        lblCounter = new JLabel("Total Porsi: 0 Cup", SwingConstants.CENTER);
        lblCounter.setFont(new Font("Segoe UI", Font.BOLD, 20));
        lblCounter.setForeground(new Color(251, 191, 36)); // Amber Gold

        pnlHeader.add(lblJudul);
        pnlHeader.add(lblCounter);

        // Body Buttons (Grid 5 baris)
        JPanel pnlButtons = new JPanel(new GridLayout(5, 1, 8, 8));
        pnlButtons.setBackground(new Color(248, 250, 252));

        btnGaya1 = new JButton("1. Tambah via Named Class (Kelas Terpisah)");
        btnGaya2 = new JButton("2. Tambah via Implements Frame (this)");
        btnGaya3 = new JButton("3. Tambah via Anonymous Inner Class");
        btnGaya4 = new JButton("4. Tambah via Lambda Expression (e -> ...)");
        btnReset = new JButton("5. Reset Porsi via Method Reference (this::reset)");

        btnGaya2.setActionCommand("TAMBAH_GAYA_2");
        btnReset.setBackground(new Color(239, 68, 68));
        btnReset.setForeground(Color.WHITE);

        pnlButtons.add(btnGaya1);
        pnlButtons.add(btnGaya2);
        pnlButtons.add(btnGaya3);
        pnlButtons.add(btnGaya4);
        pnlButtons.add(btnReset);

        lblStatusGaya.setFont(new Font("Segoe UI", Font.ITALIC, 12));

        root.add(pnlButtons, BorderLayout.CENTER);
        root.add(lblStatusGaya, BorderLayout.SOUTH);

        add(root);

    private void setupListeners() {
        // =====================================================================
        // GAYA 1: Named Class Terpisah
        // Menggunakan objek dari kelas khusus yang mengimplementasikan ActionListener.
        // =====================================================================
        btnGaya1.addActionListener(new TambahPorsiNamedHandler(this));

        // =====================================================================
        // GAYA 2: Frame Itu Sendiri Mengimplementasikan ActionListener
        // Melewatkan 'this' ke addActionListener. Method actionPerformed()
        // milik frame ini yang akan dieksekusi saat tombol diklik.
        // =====================================================================
        btnGaya2.addActionListener(this);

        // =====================================================================
        // GAYA 3: Anonymous Inner Class
        // Menginstansiasi objek anonim dari interface ActionListener di tempat.
        // =====================================================================
        btnGaya3.addActionListener(new ActionListener() {
            @Override
            public void actionPerformed(ActionEvent e) {
                tambahPorsi();
                lblStatusGaya.setText("Pemicu: Gaya 3 (Anonymous Inner Class)");
            }
        });

        // =====================================================================
        // GAYA 4: Lambda Expression (Standar Modern Java 8+)
        // Paling ringkas karena ActionListener adalah Functional Interface (SAM).
        // =====================================================================
        btnGaya4.addActionListener(e -> {
            tambahPorsi();
            lblStatusGaya.setText("Pemicu: Gaya 4 (Lambda Expression)");
        });

        // =====================================================================
        // BONUS GAYA 4b: Method Reference (this::resetPorsi)
        // Menunjuk langsung ke method yang memiliki signature kompatibel.
        // =====================================================================
        btnReset.addActionListener(this::resetPorsi);
    }

    // Method pembantu untuk menambah porsi
    public void tambahPorsi() {
        jumlahPorsi++;
        perbaruiLabelCounter();
    }

    // Method pembantu yang dipanggil oleh Method Reference
    private void resetPorsi(ActionEvent e) {
        jumlahPorsi = 0;
        perbaruiLabelCounter();
        lblStatusGaya.setText("Pemicu: Method Reference (Reset ke 0)");
    }

    private void perbaruiLabelCounter() {
        lblCounter.setText("Total Porsi: " + jumlahPorsi + " Cup");
    }

    public void setStatusGaya(String status) {
        lblStatusGaya.setText(status);
    }

    // =========================================================================

5. Matriks Perbandingan 4 Gaya Penulisan Listener

Gaya Penulisan Kelebihan Kekurangan Kapan Tepat Digunakan?
1. Named Class (Kelas Terpisah) Dapat digunakan ulang (reusable) di banyak tempat; memisahkan tampilan dengan logika bisnis secara tegas. Butuh mengoper referensi frame lewat constructor; file kode bertambah banyak. Logika aksi sangat panjang, rumit, atau perlu dipakai oleh beberapa form berbeda.
2. Implements di Frame (this) Semua penanganan tombol terpusat di satu method actionPerformed(); tidak memakan alokasi objek baru. Method actionPerformed() menjadi sarang blok if-else panjang jika tombolnya ada puluhan. Form kasir sederhana dengan 2–4 tombol aksi terpusat.
3. Anonymous Inner Class Logika aksi berada tepat di samping komponen tombol yang relevan; kompatibel di Java versi lama (Java 7 ke bawah). Sintaks bertele-tele (boilerplate code) dengan deklarasi kelas dan override method. Proyek warisan Java lama atau listener yang memiliki lebih dari 1 method abstract.
4. Lambda Expression & Method Ref Paling ringkas, modern, dan ekspresif. Mengeliminasi baris kode boilerplate; mudah dibaca. Hanya bisa digunakan pada Functional Interface (interface dengan tepat 1 abstract method). Rekomendasi Utama Standar Modern (Java 8+) untuk aksi tombol 1–5 baris.
💡 Rekomendasi Asisten untuk Praktikan

Gunakan Gaya 4 (Lambda Expression) untuk aksi tombol ringkas: btn.addActionListener(e -> hitungTotal());. Jika aksi membutuhkan pengecekan banyak kondisi, buat method pembantu (seperti hitungTotal()) lalu panggil method tersebut dari dalam lambda!

6. Satu Listener Melayani Banyak Tombol: getSource() vs getActionCommand()

Jika Anda menggunakan Gaya 2 (atau satu lambda untuk beberapa tombol), Anda perlu membedakan tombol mana yang sedang ditekan:

Pembedaan Sumber Aksi 
// CARA 1: Menggunakan getSource() (Membandingkan referensi objek komponen)
if (e.getSource() == btnTambah) {
    tambahPorsi();
} else if (e.getSource() == btnReset) {
    resetPorsi();
}

// CARA 2: Menggunakan getActionCommand() (Membandingkan string perintah)
String cmd = e.getActionCommand();
if ("TAMBAH".equals(cmd)) {
    tambahPorsi();
} else if ("RESET".equals(cmd)) {
    resetPorsi();
}
⚠️ Awas: Jebakan == vs .equals() pada String!

Jangan pernah menulis: if (e.getActionCommand() == "TAMBAH")!
Operator == di Java membandingkan alamat memori (referensi objek). Jika String berasal dari input runtime yang berbeda, kondisi tersebut akan bernilai false meskipun teksnya bertuliskan "TAMBAH"!
Gunakan selalu: "TAMBAH".equals(e.getActionCommand()).

Katalog Lengkap Interface Listener & Adapter Class

Menjelajahi ragam interface listener untuk berbagai interaksi pengguna: perubahan status item, gestur mouse, ketikan keyboard, fokus kursor, pergeseran slider, hingga siklus hidup jendela, serta bagaimana Adapter Class membebaskan kita dari penulisan method kosong.

🎯 Tujuan Pembelajaran

  • Membedakan status seleksi pada ItemListener via ItemEvent.SELECTED vs DESELECTED.
  • Menangkap gestur fisik pengguna menggunakan MouseListener, MouseMotionListener, dan KeyListener.
  • Memahami fungsi dan cara kerja Adapter Classes (MouseAdapter, KeyAdapter, WindowAdapter, FocusAdapter).

1. Mengapa Ada Banyak Jenis Listener di Java Swing?

Setiap komponen visual memiliki jenis interaksi yang berbeda: Sebuah tombol diklik (Action), sebuah kotak centang diubah statusnya (Item), kursor mouse melintas di atas gambar (Mouse), atau pengguna mengetik angka di kolom input (Key/Document). Karena itu, Java Swing menyediakan antarmuka spesifik untuk masing-masing kebutuhan.

2. Katalog Interface Listener Esensial

🔘 1. ActionListener (Aksi Penekanan Utama)

Kapan Dipakai: Saat pengguna menekan tombol JButton, menekan tombol Enter di JTextField, memilih menu di JMenuItem, atau memilih opsi di JComboBox.

Daftar Method: Hanya memiliki 1 method: void actionPerformed(ActionEvent e).

// Menangani aksi Enter pada kolom pencarian
txtCari.addActionListener(e -> {
    String kataKunci = txtCari.getText();
    System.out.println("Mencari menu: " + kataKunci);
});

⚠️ Jebakan Umum: Lupa memanggil addActionListener sehingga tombol terasa bisu dan tidak merespon saat diklik.

☑️ 2. ItemListener (Perubahan Status Seleksi)

Kapan Dipakai: Pada komponen yang memiliki status biner (terpilih / tidak terpilih): JCheckBox, JRadioButton, atau pemilihan item di JComboBox.

Daftar Method: void itemStateChanged(ItemEvent e).

chkOatMilk.addItemListener(e -> {
    if (e.getStateChange() == ItemEvent.SELECTED) {
        System.out.println("Susu Oat ditambahkan (+Rp 6.000)");
    } else if (e.getStateChange() == ItemEvent.DESELECTED) {
        System.out.println("Susu Oat dibatalkan");
    }
});

⚠️ Jebakan Umum: Mengira itemStateChanged() hanya dipanggil saat mencentang. Padahal method ini dipanggil DUA KALI saat pengguna mengganti pilihan RadioButton (1x untuk deselect item lama, 1x untuk select item baru). Selalu periksa dengan e.getStateChange() == ItemEvent.SELECTED!

🖱️ 3 & 4. MouseListener & MouseMotionListener (Gestur Kursor)

Kapan Dipakai: Menghasilkan efek visual interaktif saat kursor melintas di atas kartu produk (hover), mendeteksi klik ganda (*double click*), atau menggambar pola latte art pada panel kanvas.

Daftar Method MouseListener:

  • mouseClicked(MouseEvent e) - Terjadi setelah siklus pressed & released tuntas di titik yang sama
  • mousePressed(MouseEvent e) - Tombol mouse mulai ditekan ke bawah
  • mouseReleased(MouseEvent e) - Tombol mouse dilepaskan ke atas
  • mouseEntered(MouseEvent e) - Kursor mouse memasuki area batas komponen
  • mouseExited(MouseEvent e) - Kursor mouse keluar meninggalkan area komponen

Daftar Method MouseMotionListener:

  • mouseMoved(MouseEvent e) - Kursor digerakkan di atas komponen
  • mouseDragged(MouseEvent e) - Kursor digerakkan sambil menahan tombol klik

⌨️ 5. KeyListener (Ketikan Keyboard)

Kapan Dipakai: Memfilter karakter input (misal: nomor meja hanya boleh angka), shortcut keyboard (Esc untuk membatalkan form), atau navigasi game.

Daftar Method:

  • keyPressed(KeyEvent e) - Tombol fisik ditekan (menghasilkan getKeyCode() mis. VK_ENTER, VK_F1, VK_ESCAPE)
  • keyTyped(KeyEvent e) - Karakter teks unicode dihasilkan (menghasilkan getKeyChar() mis. 'a', '9', '%')
  • keyReleased(KeyEvent e) - Tombol fisik dilepas
// Memfilter input agar hanya menerima angka:
txtPorsi.addKeyListener(new KeyAdapter() {
    public void keyTyped(KeyEvent e) {
        char c = e.getKeyChar();
        if (!Character.isDigit(c)) {
            e.consume(); // Batalkan karakter non-angka!
        }
    }
});

🎯 6. FocusListener (Perpindahan Fokus Kursor)

Kapan Dipakai: Menciptakan efek teks placeholder bantuan pada kolom input atau memicu validasi saat pengguna selesai mengisi dan berpindah ke kolom berikutnya.

Daftar Method: focusGained(FocusEvent e) dan focusLost(FocusEvent e).

📝 7. DocumentListener (Pemantauan Teks Real-Time)

Kapan Dipakai: Menghitung sisa karakter catatan pesanan atau memperbarui estimasi subtotal secara live saat teks diketik, di-paste, maupun di-delete.

Daftar Method: insertUpdate(DocumentEvent e), removeUpdate(DocumentEvent e), dan changedUpdate(DocumentEvent e).

💡 Keunggulan Utama: Berbeda dengan KeyListener, DocumentListener tetap terpicu meskipun teks diubah menggunakan mouse (klik kanan Paste atau Cut)! Pasang selalu via textField.getDocument().addDocumentListener(...).

🎚️ 8. ChangeListener (Slider & Spinner Nilai)

Kapan Dipakai: Memantau pergeseran nilai pada JSlider (tingkat kemanisan gula 0%–100%) atau JSpinner (kuantitas porsi).

Daftar Method: void stateChanged(ChangeEvent e).

📋 9. ListSelectionListener (Seleksi Daftar JList)

Kapan Dipakai: Saat pengguna memilih baris dari daftar JList (misal memilih varian biji kopi: Gayo, Kintamani, Toraja) atau baris pada JTable.

Daftar Method: void valueChanged(ListSelectionEvent e).

⚠️ Trik Wajib: Selalu bungkus kode Anda dengan if (!e.getValueIsAdjusting()) { ... } agar aksi tidak dieksekusi ganda saat mouse masih dalam proses klik geser!

🪟 10. WindowListener (Siklus Hidup Jendela JFrame)

Kapan Dipakai: Memunculkan kotak dialog konfirmasi pop-up saat tombol silang (X) ditekan agar transaksi kasir yang belum disimpan tidak hilang tak sengaja.

Daftar Method: windowClosing(), windowOpened(), windowClosed(), windowIconified(), windowDeiconified(), windowActivated(), windowDeactivated().

3. Masalah Interface Bloat & Solusi Penyelamat: Adapter Classes

Mari kita cermati masalah besar pada WindowListener: interface ini memiliki 7 method abstract. Jika Anda mengimplementasikan interface WindowListener secara langsung hanya untuk menangani windowClosing(), Anda diwajibkan oleh compiler Java untuk menulis 6 method kosong lainnya:

❌ Tanpa Adapter: Mengotori Kode dengan Method Kosong
frame.addWindowListener(new WindowListener() {
    public void windowClosing(WindowEvent e) { konfirmasiKeluar(); }
    public void windowOpened(WindowEvent e) {}      // Kosong tak terpakai!
    public void windowClosed(WindowEvent e) {}      // Kosong tak terpakai!
    public void windowIconified(WindowEvent e) {}   // Kosong tak terpakai!
    public void windowDeiconified(WindowEvent e) {} // Kosong tak terpakai!
    public void windowActivated(WindowEvent e) {}   // Kosong tak terpakai!
    public void windowDeactivated(WindowEvent e) {} // Kosong tak terpakai!
});

Untuk menyelamatkan kita dari kode sampah di atas, Java Swing menyediakan Adapter Classes (seperti WindowAdapter, MouseAdapter, KeyAdapter, FocusAdapter).

Adapter class adalah abstract class yang sudah mengimplementasikan seluruh method interface dengan kurung kurawal kosong {}. Anda cukup meng-extends adapter tersebut dan meng-override HANYA SATU method yang Anda butuhkan!

✅ Dengan Adapter: Sangat Bersih & Fokus
frame.addWindowListener(new WindowAdapter() {
    @Override
    public void windowClosing(WindowEvent e) {
        konfirmasiKeluar();
    }
});
💡 Mengapa ActionListener Tidak Memiliki Adapter?

Perhatikan baik-baik: Ada MouseAdapter, KeyAdapter, dan WindowAdapter, tetapi TIDAK ADA ActionAdapter! Mengapa? Karena ActionListener hanya memiliki 1 method tunggal (actionPerformed). Tidak ada method kosong yang perlu dihindari, dan sejak Java 8 ia langsung dapat ditulis sebagai satu baris lambda e -> ...!

    private void setupAdapters() {
        // =====================================================================
        // 1. MouseAdapter pada Kartu Menu
        // Hanya meng-override mouseEntered, mouseExited, dan mouseClicked.
        // Tanpa adapter, kita terpaksa menulis mousePressed dan mouseReleased kosong!
        // =====================================================================
        cardMenu.addMouseListener(new MouseAdapter() {
            @Override
            public void mouseEntered(MouseEvent e) {
                // Efek hover: ubah warna latar kartu menjadi kuning lembut
                cardMenu.setBackground(new Color(254, 243, 199));
                cardMenu.setBorder(BorderFactory.createCompoundBorder(
                        BorderFactory.createLineBorder(new Color(245, 158, 11), 2),
                        BorderFactory.createEmptyBorder(12, 15, 12, 15)
                ));
                lblLogAksi.setText("MouseAdapter: mouseEntered pada kartu!");
            }

            @Override
            public void mouseExited(MouseEvent e) {
                // Kembalikan ke warna default
                cardMenu.setBackground(Color.WHITE);
                cardMenu.setBorder(BorderFactory.createCompoundBorder(
                        BorderFactory.createLineBorder(new Color(203, 213, 225), 2),
                        BorderFactory.createEmptyBorder(12, 15, 12, 15)
                ));
                lblLogAksi.setText("MouseAdapter: mouseExited dari kartu");
            }

            @Override
            public void mouseClicked(MouseEvent e) {
                lblLogAksi.setText(String.format("MouseAdapter: Kartu diklik pada koordinat (%d, %d)", e.getX(), e.getY()));
            }
        });

        // =====================================================================
        // 2. FocusAdapter pada JTextField untuk Placeholder Teks
        // =====================================================================
        txtNomorMeja.addFocusListener(new FocusAdapter() {
            @Override
            public void focusGained(FocusEvent e) {
                if (txtNomorMeja.getText().equals("Contoh: 04")) {
                    txtNomorMeja.setText("");
                    txtNomorMeja.setForeground(Color.BLACK);
                }
            }

            @Override
            public void focusLost(FocusEvent e) {
                if (txtNomorMeja.getText().trim().isEmpty()) {
                    txtNomorMeja.setText("Contoh: 04");
                    txtNomorMeja.setForeground(Color.GRAY);
                }
            }
        });

        // =====================================================================
        // 3. KeyAdapter pada JTextField untuk Validasi Angka & Tombol Enter
        // =====================================================================
        txtNomorMeja.addKeyListener(new KeyAdapter() {
            @Override
            public void keyTyped(KeyEvent e) {
                char c = e.getKeyChar();
                // Tolak jika bukan digit angka
                if (!Character.isDigit(c)) {
                    e.consume(); // Mengabaikan input agar tidak tertulis di kolom
                    lblLogAksi.setText("KeyAdapter: Hanya boleh memasukkan angka untuk nomor meja!");
                }
            }

            @Override
            public void keyPressed(KeyEvent e) {
                if (e.getKeyCode() == KeyEvent.VK_ENTER) {
                    lblLogAksi.setText("KeyAdapter: Enter ditekan! Meja terverifikasi: " + txtNomorMeja.getText());
                }
            }
        });

        // =====================================================================
        // 4. WindowAdapter pada Frame untuk Dialog Konfirmasi Keluar
        // Menangani windowClosing tanpa perlu mengimplementasikan 6 method window lainnya!
        // =====================================================================
        addWindowListener(new WindowAdapter() {
            @Override
            public void windowClosing(WindowEvent e) {
                int jawaban = JOptionPane.showConfirmDialog(
                        AdapterListenerDemo.this,
                        "Apakah Anda yakin ingin menutup aplikasi kasir JavaCafe?",
                        "Konfirmasi Keluar",
                        JOptionPane.YES_NO_OPTION,
                        JOptionPane.QUESTION_MESSAGE
                );

                if (jawaban == JOptionPane.YES_OPTION) {
                    System.exit(0); // Tutup aplikasi
                } else {
                    lblLogAksi.setText("Penutupan dibatalkan oleh kasir.");
                }
            }
        });
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> new AdapterListenerDemo().setVisible(true));
    }

    private void setupListeners() {

            public void changedUpdate(DocumentEvent e) { updateNama(); }

                String nama = txtNama.getText();
                int len = nama.length();
                lblCharCount.setText(len + "/20 Karakter");

                if (len > 20) {
                    lblCharCount.setForeground(Color.RED);
                    lblPreviewNama.setText("⚠️ Nama terlalu panjang!");
                    lblPreviewNama.setForeground(Color.RED);

                    lblPreviewNama.setForeground(new Color(30, 58, 138));

                }
            }
        });

        // =====================================================================
        // 3. KeyAdapter pada txtMeja (Filter Hanya Angka & Batas 2 Digit)
        // =====================================================================
        txtMeja.addKeyListener(new KeyAdapter() {
            @Override
            public void keyTyped(KeyEvent e) {
                char c = e.getKeyChar();
                // Hanya izinkan digit angka
                if (!Character.isDigit(c)) {
                    e.consume(); // batalkan karakter non-angka
                    return;
                }
                // Batasi panjang maksimal 2 digit
                if (txtMeja.getText().length() >= 2 && !txtMeja.getText().equals("Nomor meja...")) {
                    e.consume();
                }
            }
        });

        // =====================================================================
        // 4. ActionListener pada Tombol Konfirmasi
        // =====================================================================
        btnDaftar.addActionListener(e -> {
            String nama = txtNama.getText().trim();
            String meja = txtMeja.getText().trim();

            if (nama.isEmpty() || nama.length() > 20 || meja.isEmpty() || meja.equals("Nomor meja...")) {
                JOptionPane.showMessageDialog(this,
                        "Mohon lengkapi formulir dengan benar:\n- Nama 1-20 karakter\n- Nomor meja valid (angka)",
                        "Validasi Gagal", JOptionPane.WARNING_MESSAGE);
                return;
            }

            JOptionPane.showMessageDialog(this,
                    String.format("Meja Berhasil Dipesan!\nNama: %s\nNomor Meja: %s", nama, meja),
                    "Sukses", JOptionPane.INFORMATION_MESSAGE);
        });
    }

    // =========================================================================
    // Keyboard Focus Dispatcher (Shortcut Hotkeys F1 & F2 Aktif di Seluruh Window)
    // =========================================================================
    private void setupGlobalHotkeys() {
        KeyboardFocusManager.getCurrentKeyboardFocusManager().addKeyEventDispatcher(new KeyEventDispatcher() {
            @Override
            public boolean dispatchKeyEvent(KeyEvent e) {
                if (e.getID() == KeyEvent.KEY_PRESSED) {
                    if (e.getKeyCode() == KeyEvent.VK_F1) {
                        cardLayout.show(containerKartu, HALAMAN_KATALOG);
                        return true;
                    } else if (e.getKeyCode() == KeyEvent.VK_F2) {
                        bukaHalamanCheckout();
                        return true;
                    }
                }
                return false;
            }
        });
    }

    // =========================================================================
    // WindowListener (Mencegah Kehilangan Data saat Window Ditutup)
    // =========================================================================
    private void setupWindowProtection() {
        addWindowListener(new WindowAdapter() {
            @Override
            public void windowClosing(WindowEvent e) {
                if (hargaTerpilih > 0) {
                    int konfirmasi = JOptionPane.showConfirmDialog(
                            Level3_JavaCafeProPOS.this,
                            "Masih ada pesanan aktif (" + menuTerpilih + ") yang belum dibayar!\nYakin ingin keluar dari kasir?",
                            "Peringatan Transaksi Aktif",
                            JOptionPane.YES_NO_OPTION,
                            JOptionPane.WARNING_MESSAGE
                    );
                    if (konfirmasi == JOptionPane.YES_OPTION) {
                        System.exit(0);
                    }
                } else {
                    System.exit(0);
                }
            }
        });
    }

3. Kotak Awas: Empat Kesalahan Maut Event Handling

⚠️ 1. Lupa addActionListener

Tombol sudah dibuat dan method logika perhitungan sudah rapi, namun saat tombol diklik tidak ada reaksi apa-apa. Selalu telusuri baris inisialisasi: apakah btn.addActionListener(...) sudah terpanggil?

⚠️ 2. Listener Terdaftar Ganda (Double Firing)

Dialog sukses muncul dua kali berturut-turut saat tombol ditekan sekali. Ini terjadi jika Anda tidak sengaja memanggil addActionListener dua kali pada objek tombol yang sama (misal di constructor dan di method setupEvents()).

⚠️ 3. Menaruh Proses Berat di Listener Bikin GUI Membeku (EDT Freeze)

Seluruh event dieksekusi di satu thread: Event Dispatch Thread (EDT). Jika Anda memanggil Thread.sleep(5000) atau membaca file harddisk raksasa di dalam actionPerformed(), jendela aplikasi akan menjadi putih, membeku, dan berstatus "Not Responding" karena EDT dilarang merender layar selama proses tersebut!

⚠️ 4. Salah Pilih: keyTyped vs keyPressed

Jika Anda ingin mendeteksi tombol Panah, Shift, Ctrl, atau tombol F1–F12, jangan gunakan keyTyped! Tombol modifier hardware tidak menghasilkan karakter teks sehingga tidak memicu keyTyped. Gunakan selalu keyPressed dengan e.getKeyCode() == KeyEvent.VK_....

Kotak Dialog Pop-Up dengan JOptionPane

Menampilkan pesan pop-up konfirmasi, peringatan stok, dan pemberitahuan transaksi sukses menggunakan JOptionPane.showMessageDialog, memahami sifat jendela modal, serta menyematkan Custom Icon bergambar produk.

🎯 Tujuan Pembelajaran
  • Memahami konsep dialog modal (memblokir interaksi jendela induk hingga di-dismiss).
  • Menguasai variasi parameter pada JOptionPane.showMessageDialog().
  • Membedakan tipe pesan: INFORMATION_MESSAGE, WARNING_MESSAGE, ERROR_MESSAGE, dan PLAIN_MESSAGE.
  • Menyematkan ikon kustom (ImageIcon) pada kotak dialog sukses.

1. Apa Itu JOptionPane & Sifat Modal?

JOptionPane adalah kelas utilitas bawaan Java Swing yang sangat praktis untuk memunculkan kotak dialog standar (pop-up).

Secara default, dialog JOptionPane bersifat Modal: artinya, saat dialog ini muncul di layar, pengguna tidak bisa mengklik atau berinteraksi dengan jendela utama di belakangnya sampai mereka menekan tombol "OK" atau menutup dialog tersebut. Sifat ini sangat penting untuk memastikan pengguna benar-benar membaca konfirmasi transaksi atau peringatan error!

2. Anatomi Method showMessageDialog

Bentuk paling lengkap dari method ini menerima 5 parameter:

JOptionPane.showMessageDialog(
    parentComponent, // Jendela induk (biasanya 'this')
    message,         // Isi teks pesan konfirmasi (bisa multiline dengan \n)
    title,           // Judul pada title bar dialog pop-up
    messageType,     // Jenis ikon standar (INFORMATION, WARNING, ERROR, PLAIN)
    icon             // Objek ImageIcon kustom (opsional)
);

Bab 11 • Arsitektur Bersih

Clean Code pada GUI & Sistem Tema Terpusat

Menghilangkan kode GUI yang kusut (spaghetti code) dengan mendeklarasikan komponen sebagai atribut privat, menerapkan inisialisasi bertahap, memecah logika bisnis ke method mandiri, serta membangun kelas utilitas tema (CafeTheme) sebagai Single Source of Truth.

🎯 Tujuan Pembelajaran
  • Mendeklarasikan komponen GUI sebagai atribut privat (fields) di bagian atas kelas.
  • Membagi proses pembuatan GUI menjadi 3 tahapan: initComponents(), setupLayout(), dan setupEvents().
  • Memecah alur komputasi ke method mandiri (hitungTotal(), resetForm(), prosesCheckout()).
  • Membangun kelas utilitas tema dengan konstanta statis (warna brand, tipografi, ukuran jendela).

1. Anatomi Kelas GUI yang Bersih (Clean Architecture)

Di awal belajar, mahasiswa kerap mencampur seluruh pembuatan tombol, peletakan panel, logika hitung, dan pesan dialog ke dalam satu method constructor raksasa. Hasilnya: kode menjadi sulit dilacak saat terjadi error!

Struktur profesional kelas GUI Swing membagi kelas menjadi 5 zona teratur:

  1. Zona 1 (Fields di Atas): Deklarasi seluruh komponen visual sebagai private atribut.
  2. Zona 2 (Constructor Ramping): Hanya mengatur frame (size, close op, dsb.) dan memanggil method inisialisasi.
  3. Zona 3 (initComponents): Khusus memberi warna, font, dan teks awal pada komponen.
  4. Zona 4 (setupLayout): Khusus menyusun panel, border, dan hierarki tata letak.
  5. Zona 5 (setupEvents & Helper Methods): Khusus menangani listener dan logika perhitungan bisnis.

2. Single Source of Truth: Kelas Tema Terpusat

Bab 12 • Logika Bisnis Kasir

Pola Perhitungan Harga & Format Mata Uang Rupiah

Menguasai pola komputasi kasir: akumulasi harga dasar produk ditambah opsi add-on dinamis, memformat angka integer ke format mata uang Rupiah standar Indonesia, serta mereset formulir kembali ke kondisi awal.

🎯 Tujuan Pembelajaran
  • Menerapkan pola kalkulasi: Total = Harga Dasar + Σ(Biaya Add-on Tercentang).
  • Memformat bilangan numerik ke format mata uang Rupiah Indonesia (Locale.forLanguageTag("id-ID")).
  • Membuat fitur Reset Formulir yang mengembalikan seluruh kontrol ke status default.
  • Menyajikan rincian total transaksi secara dinamis pada label antarmuka.

1. Pola Akumulasi Harga Kasir

Pola kalkulasi kasir pada aplikasi pemesanan bekerja secara kumulatif:

  1. Mulai dengan nilai Harga Dasar produk utama.
  2. Periksa setiap JCheckBox add-on menggunakan isSelected().
  3. Jika tercentang, tambahkan biaya add-on tersebut ke variabel penampung total.
  4. Format angka total akhir menjadi teks Rupiah dan tampilkan ke JLabel.

2. Memformat Angka Menjadi Mata Uang Rupiah

Jangan pernah menampilkan angka mentah 28000 ke pengguna kasir! Antarmuka yang ramah pengguna selalu menyajikan angka dalam format mata uang: Rp28.000,00 atau Rp 28.000.

Ada dua pendekatan standar di Java:

Pendekatan A: Menggunakan NumberFormat (Standar Java Internasional)

NumberFormat nf = NumberFormat.getCurrencyInstance(Locale.forLanguageTag("id-ID"));
String teksRupiah = nf.format(35000); // Hasil: "Rp35.000,00"

Pendekatan B: Menggunakan String.format (Kustom Tanpa Koma Desimal)

String teksRupiah = String.format("Rp %,d", 35000).replace(',', '.'); // Hasil: "Rp 35.000"

3. Pola Reset Formulir

Setelah pesanan berhasil disimpan, formulir harus dikembalikan ke kondisi default agar kasir siap melayani transaksi berikutnya:

  • Seluruh checkbox add-on dimatikan: chk.setSelected(false);.
  • Label ringkasan total dikembalikan ke harga dasar awal.

 * │ + main(args: String[]): void                 │
 * └──────────────────────────────────────────────┘
 *                     │
 *                     ▼ extends
 *             ┌───────────────┐
 *             │    JFrame     │
 *             └───────────────┘
 */
public class TiketKafeApp extends JFrame {

    // Atribut privat sesuai visibilitas (-) pada UML
    private final String judulEvent = "Live Acoustic Music Night";
    private final int hargaTiket = 50000;
    private JLabel lblInfo;
    private JButton btnBeli;

    // Konstruktor publik sesuai visibilitas (+) pada UML
    public TiketKafeApp() {
        super("Pemesanan Tiket Acara Kafe - Dari UML ke Kode");
        setSize(520, 350);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setResizable(false);

        initUI();
    }

    // Method privat (-) untuk inisialisasi tampilan
    private void initUI() {
        JPanel panel = new JPanel(new BorderLayout(15, 15));

        lblInfo = new JLabel(
                String.format("<html><center><h3>%s</h3>Harga Tiket Masuk: Rp %,d<br>(Sudah termasuk 1 Welcome Drink)</center></html>",
                        judulEvent, hargaTiket),
                SwingConstants.CENTER
        );
        lblInfo.setFont(new Font("Segoe UI", Font.PLAIN, 14));

        btnBeli = new JButton("Pesan Tiket Acara Sekarang");
        btnBeli.setFont(new Font("Segoe UI", Font.BOLD, 14));
        btnBeli.addActionListener(e -> pesanTiket());

        panel.add(lblInfo, BorderLayout.CENTER);
        panel.add(btnBeli, BorderLayout.SOUTH);

        add(panel);
    }

    // Method publik (+) untuk memproses tiket
    public void pesanTiket() {
        String info = String.format("Tiket berhasil dipesan untuk:\n\"%s\"\nTotal Bayar: Rp %,d",
                judulEvent, hargaTiket);
        JOptionPane.showMessageDialog(this, info, "Konfirmasi Tiket", JOptionPane.INFORMATION_MESSAGE);
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> new TiketKafeApp().setVisible(true));
    }
}

Bab 14 • Troubleshooting

Panduan Debugging & Mengatasi Error Populer Swing

Daftar diagnosis cepat dan solusi praktis untuk lima kesalahan paling umum yang dialami praktikan saat membuat aplikasi GUI Swing: NullPointerException, komponen gaib, tombol tidak merespon, layout bertumpuk, dan gambar hilang.

🎯 Tujuan Pembelajaran
  • Mendiagnosis dan memperbaiki NullPointerException pada komponen GUI.
  • Mengatasi masalah komponen tidak muncul di layar (invisible component).
  • Mencari penyebab tombol yang dapat ditekan tetapi tidak memicu reaksi apapun.
  • Memperbaiki layout yang menimpa atau membuat komponen gepeng.

Tabel Diagnosis Error Populer & Solusi Cepat

💥 1. java.lang.NullPointerException saat Menjalankan Program

Gejala: Program langsung crash merah di console saat pertama kali dijalankan atau saat sebuah method dipanggil.

Penyebab Utama: Komponen sudah dideklarasikan di atribut kelas (misal: private JLabel lblTotal;), tetapi Anda lupa menginisialisasinya dengan kata kunci new (lblTotal = new JLabel(...)) sebelum memanggil method-nya seperti lblTotal.setText(...).

Solusi: Periksa nomor baris crash di stack trace terminal. Pastikan objek tersebut sudah di-new terlebih dahulu sebelum baris tersebut dieksekusi.

👻 2. Komponen Gaib (Sudah Dibuat tapi Tidak Tampil di Layar)

Gejala: Tidak ada error merah di console, tetapi tombol atau checkbox yang Anda buat tidak tampak sama sekali di jendela aplikasi.

Penyebab Utama: Anda sudah menginstansiasi komponen dengan new JButton(...), tetapi Anda lupa menambahkannya ke dalam container menggunakan method add(komponen)!

Solusi: Pastikan setiap komponen yang diinisialisasi dipanggil dengan panel.add(komponen) atau add(komponen).

🔇 3. Tombol Bisu (Dapat Diklik tapi Tidak Ada Reaksi Apapun)

Gejala: Tombol tampak normal di antarmuka, bisa ditekan secara visual, tetapi perhitungan tidak berjalan dan tidak ada dialog pop-up yang muncul.

Penyebab Utama: Anda sudah membuat method logika perhitungan, tetapi lupa menyambungkannya ke tombol melalui btn.addActionListener(...).

Solusi: Tambahkan baris btnSimpan.addActionListener(e -> prosesSimpan()); di method inisialisasi event Anda.

🥞 4. Layout Gepeng atau Komponen Saling Menimpa

Gejala: Tombol tampak melebar satu layar penuh, atau tombol pertama menghilang saat tombol kedua ditambahkan.

Penyebab Utama: Anda memasukkan beberapa komponen ke dalam BorderLayout tanpa menentukan posisi (sehingga semuanya menumpuk di CENTER secara default) atau menaruh lebih dari satu komponen ke region yang sama.

Solusi: Masukkan komponen-komponen tersebut ke dalam sebuah JPanel yang menggunakan FlowLayout atau GridLayout terlebih dahulu, baru kemudian masukkan panel tersebut ke BorderLayout!

🖼️ 5. Gambar ImageIcon Tidak Muncul di Komputer Lain

Gejala: Gambar muncul saat dijalankan di komputer Anda, namun hilang saat proyek dijalankan di laptop asisten.

Penyebab Utama: Penggunaan path absolut (C:\Users\...) atau kesalahan letak direktori kerja (working directory) saat IDE mengeksekusi program.

Solusi: Gunakan path relatif (assets/img/kopi.png) dan letakkan folder assets/ sejajar dengan root folder proyek Anda.

📝 Ringkasan Bab 14
  • NullPointerException selalu berarti Anda mencoba menggunakan objek yang belum di-new.
  • Komponen tidak akan muncul di layar jika Anda lupa memanggil container.add(komponen).
  • Tombol tidak akan merespon jika tidak didaftarkan ke addActionListener.
  • Gunakan selalu Nested Panel untuk mencegah komponen saling menimpa pada BorderLayout.

Glosarium Istilah GUI Java Swing

Daftar istilah dan kosakata teknis penting yang wajib dipahami oleh mahasiswa saat mempelajari Graphical User Interface di ekosistem Java.

AWT (Abstract Window Toolkit)
Pustaka GUI tertua di Java. Bersifat heavyweight karena setiap komponen bergantung pada implementasi native GUI sistem operasi underlying.
Swing
Pustaka GUI lightweight murni Java yang dibangun di atas AWT. Menghasilkan antarmuka yang seragam dan fleksibel di semua platform tanpa bergantung native OS.
EDT (Event Dispatch Thread)
Thread khusus di Java yang bertugas menangani seluruh rendering grafis dan pemrosesan event pengguna (klik, ketik). Seluruh manipulasi Swing wajib berjalan di thread ini.
Event Source
Komponen GUI visual yang menjadi pemicu timbulnya suatu aksi pengguna (misalnya: JButton yang diklik, JCheckBox yang dicentang, atau JTextField yang diketik).
Event Object
Objek turunan java.util.EventObject (seperti ActionEvent, MouseEvent, KeyEvent) yang membawa rincian data tentang kejadian yang baru saja berlangsung.
Event Listener
Interface yang mendefinisikan kontrak method penanganan aksi. Bertindak sebagai 'pendengar' yang akan dieksekusi oleh JVM saat event terkait tiba.
Adapter Class
Kelas abstrak pembantu (seperti MouseAdapter, KeyAdapter, WindowAdapter) yang mengimplementasikan seluruh method dari interface listener dengan badan kosong ({}). Memungkinkan programmer hanya meng-override method yang benar-benar dibutuhkan.
Functional Interface (SAM)
Interface yang hanya memiliki tepat SATU abstract method (Single Abstract Method). Karena sifatnya ini, ia dapat diimplementasikan secara instan menggunakan sintaks Lambda Expression (e -> ...). Contoh: ActionListener, ItemListener.
DocumentListener
Interface pemantau mutasi data teks pada model dokumen Swing (PlainDocument). Menangkap perubahan teks akibat pengetikan, Paste mouse, penghapusan tombol Backspace, maupun Cut.
JFrame
Jendela tingkat atas (top-level container) yang memiliki bingkai, judul, tombol minimize/maximize/close, dan menampung seluruh tampilan aplikasi desktop.
JPanel
Container perantara generik yang digunakan untuk mengelompokkan sejumlah komponen GUI serta mengatur tata letaknya menggunakan Layout Manager.
Layout Manager
Objek pengendali yang secara otomatis mengatur posisi, ukuran, dan penataan komponen di dalam sebuah container.
BorderLayout
Layout manager pembagi wilayah 5 arah: NORTH, SOUTH, EAST, WEST, dan CENTER.
CardLayout
Layout manager yang memperlakukan komponen sebagai tumpukan kartu yang dapat dibolak-balik (sangat ideal untuk navigasi multi-halaman).
JOptionPane
Kelas utilitas untuk memunculkan kotak dialog standar (pop-up) seperti pesan informasi, konfirmasi, input, atau peringatan.
EmptyBorder
Border tak kasat mata yang berfungsi memberikan bantalan ruang (padding/margin) di sekitar komponen agar tidak menempel ke tepi.
Dependency Injection
Pola perancangan di mana sebuah objek (misal panel) menerima dependensinya (misal frame utama) lewat parameter constructor.
